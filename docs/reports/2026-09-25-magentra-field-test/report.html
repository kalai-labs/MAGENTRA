The main complaint: "all thinking up front, then 0s"

Two causes, both in MAGENTRA, both fixed between run 2 and run 3.

CauseWhat was wrongFixProof
N1The model lost its own reasoning after every tool call. The OpenAI-compatible transport sent each earlier reply back without its reasoning. Models built to think between tool calls (MiMo, GLM-5, Kimi, DeepSeek) then plan the whole job in one block and fire the calls in a burst. MiMo's docs require the field; Fireworks: without it "the model will not have access to its previous reasoning process".Each earlier reply goes back with its reasoning as reasoning_content (engine/providers/src/openai-compat.ts). An endpoint that refuses the field gets it dropped once; one that demands it is never taught to drop it.4 tests over a real socket, incl. the real Engine end to end. Live probe: Fireworks glm-5p3 and glm-5p3-flash accept it on the first request. Side effect confirmed in run 3: the context meter is now 1.16× the measured size instead of 2.14× (it had been counting reasoning that was never sent).
N7The time went where nothing was shown. A tool call's row appeared only after the whole reply had streamed, and its timer counted only the run — milliseconds for a Write. The minutes spent writing the file showed as nothing, with a frozen token counter.The engine announces a call the moment the model starts writing it (tool_call_streaming, repeated about once a second with the characters so far), keeps the counter moving, and puts the writing time on tool_call_started. The desktop draws the row at once — "writing · 3.2k chars" — and its final time is writing + run.7 tests (engine, real slow stream, real app). Run 3: 52 of 52 calls announced while written; 188 s of writing shown; live output counter 24,252 vs 24,332 final.

Where one reply's time went (run 3, 09:51–09:53)

One reply wrote 11 modules. Before N7 this was 131 seconds of "thinking" followed by 11 rows reading 0s. Now each row appears when its file starts being written.

One thing that still looks "instant": the model chose to write all 11 files in one reply, and a reply's calls run only once the whole reply is in — so all 11 files landed on disk in the same second (09:53:26). The rows now show the writing as it happens, so the time is no longer hidden. Running each call as soon as its own arguments are complete would make the files appear one by one too (see N11).

Run 2 details (MiMo 2.6 Pro, 2026-09-24/25)

The run that exposed N1–N10. Kept here because N2, N4, N5 and N6 are still open.

The crash (N6) — why the turn ended and needed "cont"

At 03:46:58 the provider closed the connection 16 minutes into a reasoning stream. Node's fetch reports this as TypeError: terminated. withRetry (engine/providers/src/retry.ts) wraps only the request until the headers arrive; the streamed body is read later, so the error reached Session.runTurn, which ended the turn with stopReason: "error". Longer calls on the same provider had finished normally, so this was not a time limit.

Fix still to do: when the stream drops mid-reply (terminated, UND_ERR_SOCKET, ECONNRESET) and the user did not stop the turn, show "↻ the provider dropped the stream — retrying (1/3)" and re-send the same call with a backoff, up to 3 in a row. Safe, because a partial reply is never written to history.

The empty compaction summaries (N2) — how the model lost its memory

Compaction 1 (00:30) replaced 93 messages — including the original request — with one line: "No tests collected — likely a syntax error in the test file from overlapping edits. Checking." Compaction 3 was empty. runSummarizer keeps only answer text, and a reasoning model spends its 8,192-token budget thinking. Afterwards the model invented paths and usernames, grepped other projects, ran four runaway replies (all four came after a compaction) and deleted its own test file; the final self-check thought the task was "Reactor 15".

Fix still to do: run the summarizer with thinking off or low, never accept an empty or tiny summary (retry, else keep the history and say so), and carry the original request and the task board across.

The deleted test (N5)

tests/GameLiveServerTests.py (17,082 bytes) was written by the session and deleted at 01:29:34 by call 277 of a 345-call runaway reply — allow · source: mode, as OVERDRIVE is designed to do. The model rebuilt it from bytecode of an older version: 83% the same, all 72 tests passing. The exact original can be rebuilt from the transcript. Fix still to do: in OVERDRIVE, move workspace files a deletion would remove into .magentra/trash/<session>/ with a restore command.
