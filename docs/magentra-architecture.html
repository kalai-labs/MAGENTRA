MAGENTRA ARCHITECTURE MAP

A frontend (desktop app or terminal) spawns one headless engine process per workspace and talks to it over a single line-delimited JSON stream. Inside, one session runs an LLM turn loop: build the prompt, stream the model, gate and execute its tool calls against your workspace, feed the results back, repeat until the model stops. Every message is appended to a transcript in .magentra/.

Frontend process

Holds only what it needs to render and to start engines.

  • Rendered transcript as DOM, rebuilt from events (restored sessions arrive as one event).
  • App config: window, theme, recent workspaces, one tab state bundle per workspace.
  • Credentials & profiles stay in the main process; the renderer never sees a key.
  • Session log of every JSON line, redacted, under .magentra/logs.

Engine process memory

The truth while a turn is running.

  • Conversation history and queued reminders inside the single session.
  • Pending asks: unanswered permission and question requests (no timeout).
  • Context ledger: tokens per model, phases, compaction threshold.
  • Live settings, provider instance and tool registry, replaceable mid-session.

Workspace disk · .magentra/

Everything needed to resume or audit.

  • sessions/*.jsonl: append-only messages, permission decisions, compactions, per-turn stats.
  • settings.json: provider, model, permissions incl. saved always-allow rules; merged over ~/.magentra/settings.json.
  • tasks/: task lists and background output files. graph.json / symbols.json: lazily built code index.
  • .env beside it holds the API key; ~/.magentra/profiles.json holds saved connections.

Conditional · present, gated

Real code that runs only under a setting or when the model chooses it.

  • Clarify round before the first model call (on by default, skipped for addon invocations).
  • Overdrive: skips deletion guards, takes a git snapshot, adds a self-verify obligation.
  • Hooks, MCP servers, web search, vision, cron, worktrees, addons as invocable procedures.
  • Code graph and write-reuse reminder: built on demand, never at startup.

Experimental · not yet reliable

Wired end to end but with gaps visible in code.

  • Sub-agents: child task lists overwrite the parent's, no addons or hooks for children, recursion via Workflow is not blocked, child background jobs survive interrupt.
  • Workflow runner: multi-agent scripts; advertised model and phase options are ignored.
  • No automated tests guard any of this today; the test inventory exists but every feature lists zero tests.

Not runtime · left out

In the repository, not in the running product.

  • magentra-gateway: feature inventory and test gate for developers.
  • prompt-lab, version tool, benchmarks, vision_probe.py: development utilities.
  • Stale or dead: the unused protocol envelope type, the ignored --serve flag, an orphaned addon markdown copy in app/, unused counting and cron seams.
