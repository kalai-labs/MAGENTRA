1  Executive summary

Since the previous review Magentra has removed four subsystems that were registered but never shipped: the hirable crew, CAREFUL MODE, deterministic retrieval, and standing missions. That removed five prompts and two tools from every request. It did not fix the architectural finding — it isolated it.

The ratio moved the wrong way. Instructions grew 38% while tool descriptions shrank 14%. Magentra now spends nearly two-thirds of its fixed budget telling the model how to behave, where the reference spends seven-eighths describing what its tools do. Every reference build sits between 13% and 25% instructions. Magentra is at 62%.

Why this is the finding that matters. Instruction text is advice the model may or may not follow. A tool description is read at the moment of choosing that tool, and it constrains the call being made. Guidance moved from the first into the second converts a hope into a constraint — and costs nothing extra, because the tool description is already being sent.

2  Method and caveats

Magentra’s column is measured directly from the built engine: the prompt registry is enumerated with promptCatalog(), each entry resolved through promptText(), and counted with the engine’s own estimateTokens(). Tool descriptions are the prompts under the tool. namespace. The numbers are therefore what the product actually sends, not an estimate from source files.

Caveat, stated plainly. The Claude Code column is carried forward unchanged from the 28 July review. The reference corpus has not changed, but its instruction/tool split was derived by that review’s extraction method, which this one did not re-derive. The two columns are therefore comparable in magnitude and ratio, not to the token. Nothing in the findings below turns on a difference smaller than several hundred tokens.

Counts exclude conditional sections that are absent on a typical turn (project memory, atlas header, standards header) and everything sent only inside a subagent.

3  Finding 1 — The ratio moved the wrong way

Architecture

The previous review found Magentra at a 50/50 split and recommended moving guidance into tool descriptions. Four subsystems were removed since. Their tools went with them — CrewRun and BackpackSearch, 365 tokens — and so did their prompts. What remained was the instruction layer, which grew.

The removals were correct — they deleted code that never ran. But they cut the cheaper half of the budget. The result is a build that sends more fixed context than before while offering the model less information about its tools.

4  Finding 2 — Tool descriptions are thin

Tool surface

Magentra registers 27 tools and offers 26. Those 26 descriptions total 3,821 tokens — an average of 147 each. The reference builds spend roughly 20,500 tokens across a comparable tool count, averaging near 790.

system.code-style is the clearest candidate to redistribute. Most of what it says is about writing and editing files; it would apply more reliably inside Write and Edit, which are read precisely when the model is about to write or edit.

Not a call to shorten. The reference sends far more total context than Magentra does — 23,478 tokens against 10,031. The problem is not volume; it is placement. Magentra can afford to grow its tool layer substantially and still send less than half what Claude Code sends.

6  Finding 4 — Registry hygiene is now clean

Hygiene

Every prompt in the registry belongs to a shipping feature. This was not true at the last review, and the difference is worth recording:

  • Zero prompts for removed features. The crew, backpack, CAREFUL MODE, retrieval and mission prompts are gone from the registry along with their code.
  • Zero orphan prompt ids. Every id the prompt lab references resolves against the live registry, and every live prompt appears in the lab — verified in both directions.
  • Workflow is disabled deliberately. Its description is emptied, so the registry withholds it: 27 tools registered, 26 offered. This was the largest single tool description in the previous review at 604 tokens.

The prompt lab is therefore an accurate console again: what it lists is what the product sends.

7  Where Magentra is ahead

Two capabilities in the reference corpus have no equivalent, and they are worth protecting:

  • A live prompt registry. Every piece of model-facing prose is addressable by id, editable without a rebuild, overridable per workspace, and disableable by emptying it. The leaked builds have no such seam — their prompts are compiled in.
  • Deterministic end-of-turn rungs. The runtime-evidence floor and the self-verify check are enforced in code against what the turn actually did — which files it changed, whether it ever executed anything — not by asking the model to self-assess. The reference relies on instruction text for the same outcome.
