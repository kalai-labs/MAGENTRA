** THE THING TO KNOW BEFORE WRITING ANY OF THEM **
Every one of these checklists is written in terms of FakeProvider - "with a
FakeProvider scripted [...]", "the askUser stub is called once", "a FakeTurn
with error". Every one also carries your note: "Tests of this has to be done
using real LLM ... No need to write any mockup or scaffold test for this."
Those two contradict each other. Your standing rule settles it: an llm item
gets NO FakeProvider and NO scripted engine.

So each item must be TRANSLATED - from "script this response" into "give the
model an unambiguous task that forces this behaviour, then assert the engine's
observable reaction" (a file the tool wrote, a tool_call_finished, a reminder
present in the next request, a stopReason, a transcript record). Never assert
the model's wording.

These translate cleanly:

  compaction 3/4/5, resume 2/4/5.

These CANNOT be expressed against a real endpoint and should come back

  clarify 3, 4       need a scripted {clarify:false} and a scripted garbage reply

2b. windows-artifact, item 2 - A REAL PACKAGING DEFECT, FOUND BY THIS TEST
    magentra-cli.exe ships with Electron's own icon and version info instead of
    MAGENTRA's. Measured on the real 0.17.4 build:
      - all 14 code and data sections are BYTE-IDENTICAL (.text, .rdata,
        .data, .pdata, .reloc, ...)
      - .rsrc alone differs, in 53,894 of its 99,328 bytes
      - MAGENTRA.exe contains the string MAGENTRA in its resources;
        magentra-cli.exe does NOT
    Cause: app/scripts/afterPack.js writeConsoleSubsystemCopy() provably only
    reads the exe, flips the Subsystem WORD and writes the copy. electron-
    builder brands MAGENTRA.exe (icon, version info, product name - all .rsrc)
    AFTER afterPack has taken that copy, and only MAGENTRA.exe gets it.
    NOT a launch fault and NOT a UAC fault: both exes declare asInvoker,
    neither asks for requireAdministrator or highestAvailable, and both run
    ELECTRON_RUN_AS_NODE=1 <exe> resources/engine/engine.cjs --bogus
    identically (fatal error frame, exit 1).
    So it is cosmetic-but-real: wrong icon and wrong file properties on the
    terminal binary, inside the installers too.
    I did NOT guess at a fix. Moving the copy later means finding the right
    electron-builder hook - afterPack is documented as running before the
    targets are built, so a post-build fix would not reach inside the NSIS and
    portable artifacts. Each attempt costs a ~3 minute rebuild to verify, and a
    wrong guess ships a broken terminal command.
    afterPack.js is an entry file of mac-artifact, so whatever you change there
    must be restamped for EVERY record naming it (grep tests/gateway/features).
